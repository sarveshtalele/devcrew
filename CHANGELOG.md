# Changelog

All notable changes to devcrew. Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning: [SemVer](https://semver.org/).

## [1.2.0] - 2026-08-09

### Added
- `QUICKSTART.md` — ten minutes from nothing to a shipped feature, with a full `/caveman` command reference
- `template/System-Design.md` — end-to-end design principles (capacity, data model, API contract, boundaries, consistency, failure, scaling, security, observability, cost) plus a complete **zero-cost stack** table with each free tier's ceiling
- `/scout` and `/compact-docs` skills — delegated codebase search and standing-document compaction, the two largest token levers
- Brownfield adoption: `devcrew add` scans a repo once into `.devcrew/project-facts.json` so agents read the stack instead of rediscovering it
- `/project-init` now interviews on budget and system design, with a free-tier branch that records ceilings and migration paths as ADR-002
- **Design system tooling**: `make design` / `make design-check` wrap Google Labs' `@google/design.md` linter and exporters. Contrast ratios, broken token references, and section order are checked in CI and by `devcrew doctor`
- README comparison against Spec Kit and OpenSpec, including how to compose them

### Fixed
- **`Design.md` did not conform to the DESIGN.md schema it claimed to follow.** Running Google's linter against it reported 29 errors and 224 warnings: colours were nested under `light`/`dark` keys the schema has no concept of, and `gradients`, `elevation`, `motion`, and `breakpoints` were token-shaped keys the exporter silently ignores. Rewritten to the real schema — flat semantic colours with `…Dark` counterparts, the closed set of component sub-tokens, and everything unmodellable moved into prose. Now lints at **0 errors, 0 contrast findings**
- A disabled-button pairing at 4.29:1, below AA — found by the contrast rule, not by eye
- **Plugin manifest did not follow the documented schema** — `agents` must be an array of paths, not a directory string; added `displayName`
- **Hook commands did not quote `${CLAUDE_PLUGIN_ROOT}` / `$CLAUDE_PROJECT_DIR`**, which breaks on any path containing a space
- `token-report` skill now declares `allowed-tools`
- Grammar in a `devcrew doctor` warning

## [1.1.0] - 2026-08-09

### Changed
- **Renamed to `devcrew`** — CLI, package, state directory (`.devcrew/`), and environment variables (`DEVCREW_*`)
- Agents, skills, and hooks moved to `.claude/` as the single canonical source, so opening this repository in Claude Code gives the full team with no setup step; the plugin manifest points at the same directories

### Added
- **Windows support** — `install.ps1` detects Git Bash or WSL, pins `core.autocrlf false`, and writes a PATH shim
- `.gitattributes` pinning every shell script to LF, without which the hooks fail on Windows
- `Example.md` — one user story walked through all 15 stages with real artifacts
- `User-Story-Testing.md` — story to acceptance criteria to test-level assignment, with traceability and anti-patterns; wired into the product-manager, qa-engineer, e2e-automation, and code-reviewer agents and the `/test-plan` skill
- Repository hygiene: `.claude/settings.json` (the repo runs its own gates), `CODEOWNERS`, Dependabot, issue templates, `.vscode` recommendations
- CI checks that every mode references agents that exist and that agent frontmatter is well-formed

### Fixed
- `push-guard` scanned every Bash command for attribution trailers and `--no-verify`, blocking greps, tests, and documentation that legitimately mention those strings. Now scoped to real `git`/`gh` invocations, with regression tests

## [1.0.0] - 2026-08-09

### Added
- 15 department agents with isolated contexts, tool allowlists, and per-agent token budgets
- 15-stage SDLC pipeline with named owners and literal exit criteria
- 5 delivery modes (`lite`, `core`, `secure`, `ai`, `full`) selecting agents, stages, and gate strictness
- `devcrew` CLI: `init`, `add`, `mode`, `agents`, `verify`, `doctor`, `sync`, `tokens`, `uninstall`
- Universal installer (`install.sh`), npm `bin` entry, and Claude Code plugin manifest
- Deterministic agent hooks: `token-guard`, `secret-guard`, `push-guard`, `quality-gate`, `session-meter`, `changelog-nudge`
- Git hooks: `commit-msg` (blocks AI attribution, enforces Conventional Commits) and `pre-push` (blocks unverified pushes)
- Per-department Kanban+Scrum trackers and a cross-department program board
- Document templates: PRD (IEEE 29148), ADR (MADR), technical design, threat model (STRIDE + OWASP LLM), test plan (IEEE 29119), runbook, change record, DPIA
- Skills: `/project-init`, `/feature`, `/adr`, `/threat-model`, `/test-plan`, `/release`, `/token-report`
- Portable configs for Cursor, Antigravity, and GitHub Copilot, generated by `devcrew sync`
- Design system spec with light and dark token sets at WCAG 2.2 AA
- `Guide.md` — complete manual

### Security
- Baseline: OWASP ASVS L2, OWASP LLM Top 10, NIST SSDF; control maps for SOC 2, GDPR, HIPAA, and PCI DSS
- Verification gate ordering: secrets scan first, so a leaked credential is never masked by later passing checks
- AI authorship trailers blocked at three layers: agent instructions, `push-guard`, `commit-msg`
